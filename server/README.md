# 联机服务部署

[返回项目首页](../README.md)

## 构建与启动

在项目根目录执行：

```sh
pnpm install
pnpm build
pnpm --filter @xionghan/server start
```

服务端默认监听 8000 端口。生产环境将 `/games` 与 `/socket.io`（含 WebSocket）反向代理到服务端，其余请求托管 `web/dist`。

推荐网页与 API 使用同域反向代理。若使用独立服务端域名，在构建网页前设置 `VITE_API_SERVER_URL`，并把网页来源加入 `WEB_ORIGINS`；不同站点部署还会受到 SameSite Cookie 限制。

## 环境变量

| 变量                  | 默认值                                        | 用途                                                     |
| --------------------- | --------------------------------------------- | -------------------------------------------------------- |
| `PORT`                | `8000`                                        | 服务端监听端口                                           |
| `WEB_ORIGINS`         | `http://127.0.0.1:5173,http://localhost:5173` | 允许的网页来源，逗号分隔                                 |
| `DATA_DIR`            | `server/data/`                                | 房间、座位和棋谱的存储目录                               |
| `MAX_ROOMS`           | `500`                                         | 全服房间上限                                             |
| `CREATE_RATE_LIMIT`   | `5`                                           | 每个 IP 每 10 分钟可发起的建房或重开请求数，包含失败尝试 |
| `TRUST_PROXY_IPS`     | `127.0.0.1,::1,::ffff:127.0.0.1`              | 受信任代理的连接 IP，逗号分隔                            |
| `VITE_API_SERVER_URL` | 空，使用当前网页来源                          | 前端构建变量，用于指定独立 API 地址                      |

开发时使用 `pnpm dev:server`，通过 `NODE_ENV=development` 放开 Origin 检查，方便远程隧道测试；普通 `start` 启动执行来源检查。

## 代理与身份 Cookie

限流仅在连接来自受信任代理时读取 `X-Forwarded-For` 的最后一个地址。使用其他反向代理时应明确配置 `TRUST_PROXY_IPS`，并确保代理正确追加或重写转发头，避免把所有用户识别为同一 IP。

HTTPS 下的身份 Cookie 需要 `Secure` 标记：反向代理须覆盖 `X-Forwarded-Proto`，且其连接地址位于 `TRUST_PROXY_IPS`。

## 数据与房间回收

服务端使用 bgio 的 FlatFile 存储；正常停止时等待写入完成，重启后保留房间、座位和棋谱。当前仅支持单实例，不要让多个服务进程共用数据目录。尚未提供公开大厅列表和自动匹配。

过期房间每分钟扫描回收，规则如下：

| 房间状态           | 回收时间                                   |
| ------------------ | ------------------------------------------ |
| 无人入座           | 10 分钟                                    |
| 未凑齐且无人在线   | 15 分钟                                    |
| 双方离线，尚未结束 | 30 分钟                                    |
| 对局已结束         | 从结束时起保留 24 小时，在线或重连均不延长 |

未结束对局只要任何一方在线就不回收。回收会删除房间的座位、局面和棋谱，原邀请链接随后失效；需要长期保留的棋谱应提前导出。

## 公网限制

- 每个 IP 每分钟最多 120 次大厅 API 请求。
- 每个 IP 每 10 分钟最多 5 次建房或重开请求，包含失败尝试，可通过 `CREATE_RATE_LIMIT` 调整。
- 全服最多 500 个房间，并发创建也不能突破上限，可通过 `MAX_ROOMS` 调整。
- WebSocket 必须凭有效座位连接；每个 IP 最多 20 条同时连接，每分钟最多 120 条客户端事件。
- 同步不存在的房间不会自动建房。

## 匿名身份与座位恢复

首次访问由服务端签发随机匿名身份，使用 `HttpOnly; SameSite=Lax` Cookie 保存一年；HTTPS 下设置 `Secure`（反向代理须覆盖 `X-Forwarded-Proto`，且其地址位于 `TRUST_PROXY_IPS`）。推荐前端和 API 使用同域反向代理；不同站点部署会受到 SameSite Cookie 限制。

服务端将身份哈希与座位关联，独立保存于房间存储中，不公开到大厅元数据。大厅「我的对局」列出该身份尚未回收的房间：进行中可恢复座位，已结束可只读复盘或导出。复盘不覆盖本地对局，结束棋谱仍在结束 24 小时后回收，不做长期归档。旧版本最近一盘的本地座位凭据在进入大厅时自动关联；其他旧房间可通过原邀请链接恢复并关联。

清除 Cookie 或更换浏览器会产生新身份，无法凭房间号认领原身份的座位。旧版仍保存有效座位凭据的浏览器可继续以凭据恢复原座位，但不能把已绑定的座位转移给另一个身份。
