# 匈汉象棋

[查看规则](wiki/rules.md)：棋盘与初始摆法、十种棋子的走法和吃法、胜负与和棋规则，附图示说明。

## 开发

使用 Node.js 24 和 pnpm，根目录统一管理三个工作区：

- `core/`：棋盘、规则、棋谱、摆子校验与 bgio 游戏定义，供两端共用。
- `web/`：React 页面、皮肤、音效和浏览器存档。
- `server/`：最小 bgio 服务端入口。

```sh
pnpm install
pnpm dev          # 直接加载 core 源码，启动网页 http://127.0.0.1:5173
pnpm test         # core、web 和 server 的常规测试与联机集成测试
pnpm test:random  # 随机对局测试
pnpm build        # 按依赖顺序构建三个工作区
pnpm preview      # 预览 web/dist 的生产页面
pnpm dev:server   # 编译并监听 core，启动并监听服务端，默认端口 8000
```

服务端通过 `PORT` 和 `WEB_ORIGINS`（逗号分隔）配置监听端口及允许的网页来源；默认允许 `http://127.0.0.1:5173`。
生产环境先执行 `pnpm build`，再执行 `pnpm --filter @xionghan/server start`。
网页顶部的「联机对弈」可创建房间、选择红黑、分享链接或加入邀请；刷新房间链接会恢复当前浏览器保存的座位。本地对局存档与联机凭证分开保存。
开发时同时运行 `pnpm dev` 和 `pnpm dev:server`，后者使用开发模式，不限制 Origin，方便通过远程隧道测试；普通 `start` 启动仍执行来源检查。网页通过 Vite 代理访问服务端，无需把 8000 端口写进邀请链接。可用另一浏览器或无痕窗口模拟对手。
生产环境将 `/games` 与 `/socket.io`（含 WebSocket）反向代理到服务端，其余请求托管 `web/dist`；若使用独立服务端域名，在构建网页前设置 `VITE_API_SERVER_URL`，并把网页来源加入 `WEB_ORIGINS`。

服务端使用 bgio 的 FlatFile 存储，数据默认保存在 `server/data/`，可通过 `DATA_DIR` 指定目录；正常停止时等待写入完成，重启后保留房间、座位和棋谱。当前仅支持单实例，不要让多个服务进程共用这个目录。尚未提供公开大厅列表和自动匹配。

公网服务默认限制：每个 IP 每分钟最多 120 次大厅 API 请求、每 10 分钟最多 5 次建房或重开请求（包含失败尝试），全服最多 500 个房间，并发创建也不能突破上限。WebSocket 必须凭有效座位连接，每个 IP 最多 20 条同时连接，每分钟最多 120 条客户端事件；同步不存在的房间不会自动建房。可用 `CREATE_RATE_LIMIT` 和 `MAX_ROOMS` 调整建房频率及容量。
过期房间每分钟扫描回收：无人入座 10 分钟，未凑齐且无人在线 15 分钟，双方离线 30 分钟，已结束对局从结束时起保留 24 小时，在线或重连均不延长。未结束对局只要任何一方在线就不回收。回收会删除该房间的座位、局面和棋谱，原邀请链接随后失效。
限流仅在连接来自受信任代理时读取 `X-Forwarded-For` 的最后一个地址。`TRUST_PROXY_IPS` 默认只信任本机回环地址；使用其他反向代理时应明确填入代理的连接 IP，并确保代理正确追加或重写转发头，避免把所有用户识别为同一 IP。

## 已实现

- **人机对战**：顶部「人机」选择执红或执黑，Rust AB 引擎通过 WASM 在 Worker 中运行，每步思考约 3 秒；支持刷新恢复，WASM 随 PWA 缓存。切换模式会确认开启新局，导入棋谱后回到同屏模式。

    支持 WebMCP 的浏览器在人机模式下可调用 `xionghan_get_position` 读取局面与合法走法，再用返回的 `positionId`、`from`、`to` 调用 `xionghan_move` 代玩家走棋。电脑回合、复盘、摆子和结束后禁止落子；退出人机模式时移除入口。不支持 WebMCP 的浏览器仍可正常手动对弈。

- **联机对弈**：建房、邀请加入、执黑翻转、断线重连、刷新恢复及服务端持久化；联机时复用现有棋盘、棋谱、皮肤和音效。

- **皮肤**：导入含 `skin.properties` 的 ZIP 皮肤包，按 ID 更新，支持切换、删除与刷新恢复；可单独替换棋盘、棋子和页面背景；棋谱、联机操作区、菜单、弹窗、棋盒与大厅卡片统一使用 `panel.9.png`（单段点九图）或 `panel.png`，缺少的资源继续使用默认绘制。旧包中的 `record.9.png` / `record.png` 仅在没有通用面板时作为后备，不再独立渲染棋谱。

- **棋谱**：自动记录每步走法，支持查看起始局面、逐步浏览和返回最新局面，随对局一起保存；查看历史时暂停落子。

- **自动保存与恢复**：保存当前局面、行棋方、上一步、胜负状态、摆子草稿和音效开关，刷新或重新打开后自动恢复。
- **安装与离线使用**：支持安装到桌面或主屏幕；首次联网加载后，可离线对弈和摆子，字体与音效一并缓存；发现新版本时提示更新，由用户确认后激活并刷新。
- **默认棋盘**：13×13 棋盘，双方各 22 枚棋子，按默认布局开局。
- **同屏双人对弈**：红方先行，双方轮流走棋；点选己方棋子后，点击合法落点移动或吃子。
- **十种棋子规则**：包含马的日字与直三、兵过长城、锐沿斜轨行走、卫在空心点间横行，以及檑的特殊吃子限制。
- **合法性检查**：校验棋子归属、移动路径、阻挡和吃子条件，禁止两王照面及使己方王受到攻击的走法。
- **局面提示**：显示选中棋子、合法落点、可吃目标、上一步位置、当前行棋方和将军状态。
- **胜负判定与新局**：将死或困毙时判负；可重新开局，已有走子时需确认。
- **键盘操作**：方向键移动棋盘焦点，Enter 或空格选子、落子，Escape 取消选择。
- **音效开关**：选子、走棋、吃子、将军和胜负音效，默认开启，可在页面顶部随时切换。
- **摆子模式**：编辑当前局面、补子和移除棋子，可清空非王棋子或恢复默认布局；校验通过后从摆好的局面开始对弈，也可取消并返回原对局。

### 棋谱文件

对局菜单支持「导出棋谱」；本地模式还支持「导入棋谱」。导出为带版本号的匈汉象棋 JSON 文件，包含初始局面、完整走棋记录和当前轮次，不包含联机座位凭据或浏览器偏好。导入校验通过后仍需确认，确认才替换当前本地对局，并从起始局面打开复盘；回到最新局面可以继续本地对弈。

目前只支持本项目导出的 `xionghan-record` v1 格式，文件上限 10 MB、20000 手。导出的文件保存在用户本地，不受服务端房间回收影响。

### 匿名身份与我的对局

首次访问由服务端签发随机匿名身份，使用 `HttpOnly; SameSite=Lax` Cookie 保存一年；HTTPS 下设置 `Secure`（反向代理须覆盖 `X-Forwarded-Proto`，且其地址位于 `TRUST_PROXY_IPS`）。推荐前端和 API 使用同域反向代理；不同站点部署会受到 SameSite Cookie 限制。

服务端将身份哈希与座位关联，独立保存于房间存储中，不公开到大厅元数据。大厅「我的对局」列出该身份尚未回收的房间：进行中可恢复座位，已结束可只读复盘或导出。复盘不覆盖本地对局，结束棋谱仍在结束 24 小时后回收，不做长期归档。旧版本最近一盘的本地座位凭据在进入大厅时自动关联；其他旧房间可通过原邀请链接恢复并关联。

清除 Cookie 或更换浏览器会产生新身份，无法凭房间号认领原身份的座位。旧版仍保存有效座位凭据的浏览器可继续以凭据恢复原座位，但不能把已绑定的座位转移给另一个身份。

## 皮肤包规范

ZIP 根目录必须包含 UTF-8 的 `skin.properties`，`id` 与 `name` 必填，`author`、`version`、`description` 可选。同 ID 再次导入会更新皮肤。

- `background.png`：页面背景，居中 cover。
- `board.png`：棋盘与网格，按棋盘尺寸 fitXY。
- `r-*.png` / `b-*.png`：双方棋子，按棋子区域 contain。
- `panel.9.png`：所有 UI 容器共用的面板，优先于 `panel.png`。点九边缘每边只支持一段纯黑标记，其余透明；上、左标记拉伸区，下、右标记内容区。容器保留必要的内边距，且不会小于内容区标记。普通 `panel.png` 则随容器拉伸。

可在 `skin.properties` 中选配以下共用颜色，值仅接受 `#RGB`、`#RGBA`、`#RRGGBB` 或 `#RRGGBBAA`；未填写时沿用默认色，不支持任意 CSS：

```properties
color.text=#584a39
color.muted=#8b8070
color.border=#c9bdab
color.surface=#f6f2e9
color.accent=#a1332d
color.accent-text=#fff8ec
color.hover=#e8decd
color.selection=#e2d7c5
```

这些颜色用于 UI 文字、边线、按钮及交互状态，不会修改棋子图片、双方棋色和禁着标记。面板图片应与文字颜色配套；图片本身的颜色不会被这些变量重绘。
